# 滚球向前冲 · Windows 复活版（Web 本地版）

把一款小米快游戏发行包《滚球向前冲》（LayaAir 2.1.1.1 的 3D 滚球游戏，原包仅 3.45 MB）在 Windows 浏览器里复活、可玩的全过程记录与完整工程。

> 本仓库只放**复活桥接代码与文档**。完整的游戏包已打包进 **发行版（Releases）**，请到仓库的 Releases 页下载：
> - **游戏源文件.zip**：原始解包内容（main.js、res/ 等资源与原版 manifest.json），不含任何复活补丁——等于从 `.apk`（实为改后缀 ZIP）里直接拆出来的样子。
> - **开箱即玩版.zip**：在游戏源文件基础上加上浏览器桥接 `index.html` 与两个启动 bat，解压后双击 bat 即玩。

## 这是什么

`滚球向前冲.apk` 不是安卓 APK，而是 **LayaAir 2.1.1.1 小米快游戏发行包**（ZIP 改了后缀）。本工程把它还原为 PC 浏览器可玩的网页版。

- 引擎：LayaAir 2.1.1.1（3D 渲染管线，WebGL）
- 设计分辨率：720×1280 竖屏
- 原包：压缩 3.6MB / 解压 11.5MB

## 怎么跑（开箱即玩版）

从仓库 **Releases** 页下载 `开箱即玩版.zip`，解压后得到 `开箱即玩版/` 文件夹，进入该文件夹，双击两个启动器之一即可（都会自动起本地服务器并弹出游戏页；服务器在最小化的命令行窗口里，玩完关掉它即可）：

| 启动器 | 作用 |
|---|---|
| `开始游戏（读取进度）.bat` | 正常启动，沿用浏览器里已有的存档（钥匙、皮肤、已解锁关卡） |
| `开始游戏（重置进度）.bat` | 先清空存档再启动，回到全新状态（等同第一次玩） |

「重置进度」怎么实现的：该启动器打开的地址带 `?reset=1`，`index.html` 在 `main.js` **之前**发现这个参数就删掉 `localStorage["userData"]`（整个进度就这一个键），随即用 `history.replaceState` 把参数抹掉——所以只在这一次生效，之后刷新或正常启动都照常读档。

或手动：

```
D:\B++\Py313\python.exe -m http.server 8123 --directory 开箱即玩版
```

然后浏览器开 **http://127.0.0.1:8123**（必须 HTTP，不能 file:// 直开；重置进度则开 `http://127.0.0.1:8123/?reset=1`）。

- 改过 `index.html` 后要 **Ctrl+F5 强刷**。
- 首次进入浏览器会拦音频自动播放，**点一下画面**即可出声。
- 平台能力按浏览器路径处理（`platform="web"`）：激励视频类按钮会「立即回调成功」，所以「马上挑战」「随机选择」等原本要播广告的按钮都能直接用，不会卡住。

## 操作

| 操作 | 方式 |
|---|---|
| 进关 | 主菜单「关卡模式」→「开始游戏」→ 选皮肤弹窗里点任意球（Ball_01~09 均可直接选），或点「随机选择」 |
| 挑战模式 | 主菜单「挑战模式」→ 弹窗里点「马上挑战」直接开始（第 1000 关，含手势引导）；点「不了谢谢」关闭弹窗 |
| 滚球 | 方向键 ← ↑ → ↓ 或 **W A S D**（键盘），也可用画面上的虚拟方向键 |
| 视角左右切换 | **Q / E** 键，或关卡右侧 HUD 的视角按钮 |
| 跳过本段 / 相机 / 回正 | 关卡右侧 HUD 按钮 |

选皮肤弹窗里九个球全部可直接点击选中（无需看广告），点球即装备该皮肤并进入第 1 关；「随机选择」会从未解锁皮肤里随机抽一个并解锁，「不了谢谢」直接用当前皮肤开始本关（原版行为）。

注意：「不了谢谢」在原版里就是**弹窗底部一行纯文字**，没有按钮外壳、也没有按下态反馈，所以点它「看起来没动静」是正常的视觉印象——真正的判据是弹窗有没有关掉、有没有进关。

## 点了按钮没反应？按 F9 开诊断浮层

游戏页里随时按 **F9** 开关左上角的诊断浮层（地址栏加 `?debug=1` 也能直接以诊断模式启动）：

```
滚球向前冲 诊断 v2026-10-16.2
视口 1536x864 @1.25
桥接目标 yes(720x1280)
点击 3  最后 (768,673)
兜底 触发 0 次
不了谢谢 节点 1 个
皮肤弹窗在
F9 关闭
```

- **每次鼠标左键按下，屏幕上留一个红点**（1.8 秒后消失）。红点落在哪，就是游戏收到的点击在哪。
- 第 3 行「桥接目标」必须是 `yes(...)`；若是 `NO`，说明输入桥接没找到渲染画布，**所有点击都会被静默丢弃**（这正是「画面正常但按钮点不动」的典型症状）。
- 「不了谢谢 节点」= 当前页面上找到的那张「不了谢谢」图片数量（皮肤弹窗 / 解锁挑战弹窗各有一张）。`0 个` 说明此时没有这个弹窗。
- 「兜底 触发」= 第 ④ 层（点击兜底）救回的次数。它 >0 说明引擎自己没把点击派发给「不了谢谢」，是兜底补上的——正常命中时它应该一直是 0。
- 最后一行是实时面板状态：`皮肤弹窗在` = 弹窗还开着；`【已进关】` = 已经进了关卡。

对照「不了谢谢」点下去没反应这件事：

| 现象 | 含义 | 怎么办 |
|---|---|---|
| 红点不出现、「点击」数字不涨 | 页面根本没收到鼠标事件 | 先 **Ctrl+F5 强刷**；再换鼠标试、点一下页面给焦点、关掉浏览器扩展 |
| 红点压住了「不了谢谢」，最后一行仍是「皮肤弹窗在」 | 事件到了、位置也对，但按钮逻辑没跑 | 把这一屏拍照反馈 |
| 红点出现但位置偏了，没压住文字 | 坐标换算偏了（页面缩放/多显示器） | 把这一屏拍照反馈 |
| 最后一行变成「【已进关】」 | 其实成功了，已经进了第 1 关 | 无需处理 |

控制台还会打印一行入口版本号（`[滚球向前冲] 本地 Web 入口版本 v...`）——先确认它和你手上的版本一致，排除浏览器缓存旧页面的可能。

## 本次功能改进（v2026-10-16，均已实测通过）

1. **平台判定修正（关键根因）**：SDK 初始化把 `platform` 写死成 `"xiaomi"`，于是所有 `VideoAD()` 都去调小米广告 SDK——网页上没有这个 SDK，回调永不触发，按钮表现为「点了没反应」。已改为 `"web"`，走原作者本就写好的浏览器分支（激励视频立即回调成功）。这一步一次性救活了「马上挑战」「随机选择」，以及复活、挑战双倍奖励等所有广告按钮；连带**看广告解锁钥匙、皮肤、挑战模式**整条链路也通了。
2. **「看广告获得 2 个钥匙」按钮**：已改为点击直接 +2 钥匙并保存（`FreeKeyUI` 的 `Btn_AD`）。
3. **九个皮肤全部可直选**：`SelectSkinPanel` 循环里原本未解锁皮肤要先播激励视频，已改为全部直接 `SelectPiFu` 选中（`main.js`）。
4. **键盘滚球**：`GameUI.onEnable` 注册键盘监听，方向键 + WASD 映射 `Move/StopMove`（`main.js`）。
5. **Q/E 视角切换**：`PlayerControl.ChangeShiJiaoEx(0/1)` 左右转 90°（`main.js`）。
6. **相机抖动修复**：`CameraMove` 的渐进逻辑在角度到位后会每帧在「到位」和「-0.1 弧度」之间来回跳，视角持续晃。已改为带 `Math.min/Math.max` 钳位的双向渐进，到位后严格锁定（实测静止时相机旋转角恒定 0.000°）。

## index.html 做了什么（四层修复 + 一个诊断）

1. **qg 运行时垫片**（main.js 之前）：基于 HTTP 的 `readFile`/`downloadFile` 实现，让小游戏文件系统走 XHR 加载本地 `res/`；刻意不定义 `getApp`/`GameGlobal`（否则 KGMiniAdapter 反向激活，改走迷你文件系统 → 资源零请求 → 黑屏）。
2. **纯 CSS 画布适配**：小游戏构建不给画布设 CSS 尺寸（只设后备缓冲 = 逻辑尺寸 × dpr），浏览器 1:1 显示会被裁；且 main.js 包装了整套 DOM，页面 JS 写 style 落不到真元素上——只能用 CSS 把真渲染画布等比居中、把 `#layaCanvas` 和字体位图画布推到屏幕外。
3. **输入桥接**（main.js 之后）：这个包把 DOM 换成「迷你 DOM」，鼠标/触摸监听挂在假画布对象上，浏览器没人喂事件 → 在真实 window 上监听（捕获阶段），翻译成普通对象派发给迷你画布；并按实际 CSS 尺寸与 dpr 反算回逻辑坐标。
4. **点击兜底 / 死区修复**：Laya 把画布缩放比写进舞台自身 `_transform`（1366×768 下 `clientScale=0.6`，`_transform.a=0.6`）。命中测试 `fromParentPoint` 先调 `invertTransformPoint` 把点击坐标放大 `1/clientScale` 倍，点一下就被推到舞台矩形外；而 `Scene` 节点自带 `hitTestPrior=true`，`check()` 里自身矩形判定不过就整棵子树收不到事件——窗口比例不是 720:1280 时，屏幕下半部点击被整段丢弃（死区边界 = 设计高 × clientScale：1366×768 下设计 `y≥800` 全丢、1920×1080 下 `y≥1100` 才丢、720×1280 全屏正常）。修法：输入桥派发前按 clientScale 把坐标收回（`x = m.tx + csx*(x - m.tx)`），再叠一层不依赖显示列表命中的矩形补发 CLICK，正常命中的不重复触发。这一步顺带让「看广告解锁」「不了谢谢」等压在下半部的按钮都能点。
5. **F9 诊断浮层**：见上节。
